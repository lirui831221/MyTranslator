## 关键设计决策

### 1. Silero + 能量回退断句（voice.rs / neural_vad.rs）

- 麦克风帧重采样到 16 kHz；系统音频由原生 ScreenCaptureKit 助手直接输出 16 kHz 单声道 f32le。两种输入都每 32ms 送入 **Silero VAD v6.2**，开始阈值 0.52、保持阈值 0.35。
- CPU-only whisper VAD 运行时约 2.1MB，单帧约 0.05–0.1ms；避免初始化 Metal。
- 同时保留 EMA 噪声底、绝对 RMS 下限和连续 3 帧去抖；模型不可用时自动退回能量 VAD。
- VAD 异常看门狗：Silero 在强声音下连续 384ms 输出近零概率时启用受限能量回退；持续 4 秒自动重建 Silero 上下文，重建后 30 秒冷却，防止反复加载。
- 看门狗只改变断句入口，原有最短发声时长、波形 RMS/峰值门控和 Whisper 结果过滤保持不变。
- 480ms 前滚/跨边界重叠缓冲；fast 对短回复（发声≤2s且整段≤3s）在 320ms、其他句子在 420ms 形成候选句尾，再保留 220ms 后滚音频。最近的 base/medium 临时结果若以连接词、逗号或未完成结构结尾，则将总静音上限延长到 900ms；否则约 540/640ms 收句。steady 对 Silero 强静音使用 480ms、模糊停顿使用 800ms；连续讲话 5s 形成滚动硬边界。
- 对 96ms 以上、但尚未达到普通断句阈值的停顿建立 speaker-turn probe；比较停顿前 360ms 与恢复说话后 160ms 的基频、自相关置信度、8带频谱形状、过零率和对数能量。达到保守阈值时回切至新说话者起点，上一段以 `speaker_turn_end` 最终块进入 ASR，下一段使用新的 `utterance_id`。
- `speaker_turn_end` 会传播到 semantic worker；即使最终 ASR 为空、被质量门控丢弃或没有新增稳定文字，RAII 边界标记仍按 ASR 顺序刷新缓冲。不同说话人的片段禁止合并。
- `native/system-audio-capture.swift` 使用 ScreenCaptureKit 捕获显示器音轨、排除 helper 自身音频，不捕获屏幕像素；Rust 读取 stdout PCM。helper 退出时通道断开会显式报错，不会让管线永久假运行。
- 输入源切换先 `stop_voice`，等待 `VOICE_CAPTURE_ACTIVE=false` 后再重启；原子活动标志阻止旧 cpal/ScreenCaptureKit 流尚未退出时启动第二条采集线程。

### 2. 动态滚动识别与稳定前缀

- 发声 1.8s 产生首个 medium 检查点，之后约每 1.2s 对增长中的同一语句复核；base 模型继续提供更早的临时预览。
- 相邻两次 medium 结果只提交共同稳定前缀；优先在句号、问号、感叹号和分号处提交，无标点时保留末尾不稳定字符/单词。
- 5s 硬边界保留 480ms 音频重叠，下一段识别后用已提交文本的后缀与新结果前缀匹配去重。
- `voice-partial` 只显示尚未提交的尾部；稳定文字进入 `voice-heard`，不会随下一次 Whisper 改写而回跳。

### 3. 识别/翻译双流水线与过期检查点合并

- VAD 产出的 medium 检查点进入单独 ASR worker；稳定文字进入另一条 translation worker，翻译变慢时 ASR 仍可继续复核和提交原文。
- ASR 队列积压时，只合并同一 `utterance_id` 尚未执行的中间检查点，直接使用最新音频快照；不同语句不会跨句合并，`is_final=true` 的最终检查点永不丢弃。
- 两条流水线分别维护队列深度；日志输出合并数量、翻译序号和队列深度，便于诊断长时间运行后的积压。
- `LAST_SUBTITLE` 仅在译文所属原文仍是最新原文时更新，避免识别领先翻译后左右栏轮询错配。

### 4. 语义合并缓冲

- ASR 的每个稳定提交先进入 semantic worker，并携带 `fragment_id / utterance_id / epoch / is_final`，识别原文仍立即显示，不等待翻译。
- 同一语句的稳定前缀与最终尾部优先合并；没有结束标点的短片段也可与相邻短句合并，方向、模型或 epoch 不同则强制分界。
- 带结束标点、中文达到 9 字、英文达到 6 词或长度达到上限时立即刷新；增长中的语句基础等待 1.6 秒，已结束短句基础等待 0.9 秒。
- VAD 会同步“正在发声/刚结束发声”状态；短缓冲超时时若下一段说话或 ASR 仍在路上，最多延长 2 次。
- `started_at` 从首片段进入时固定，任何新片段都不能重置；绝对等待上限 3.6 秒。单批最多 3 个片段、64 字符；达到任一上限立即刷新，防止持续说话时无限延长。
- `voice-semantic-merged` 让前端把多个“翻译中”行收拢成一行；译文使用 `fragment_ids` 精确回填，避免相同文本误匹配。

### 5. ASR 异常质量门控与选择性二次识别（main.rs）

1. 声学层：Silero VAD + 三帧去抖 + 波形 RMS/峰值门控
2. **无 --prompt**：whisper 对噪声段会复读 prompt 当结果（294 次事故教训）
3. 内容黑名单：prompt 复读句 + 括号音效标记 `(...)` 整段丢弃
4. 质量评分：结合音频时长检查中文字符/英文词速率、循环重复、超长无标点输出，以及同一语句相邻检查点的大幅漂移。
5. 可疑的非最终检查点直接丢弃，等待包含更多音频的新检查点，避免阻塞 ASR 有序队列。
6. 最终结果相对上一完整检查点短到 ≤2 字或不足 35% 时追加严重 `final_collapse`；复核失败时可使用最近两个非最终检查点的严格公共稳定前缀，而不是发布退化结果。
7. 严重异常和术语一致性问题仍同步复核；普通选择性疑难句立即发布常驻 Medium 的结果，并把音频所有权移交给后台复核任务。
8. 识别模型可选 Whisper 或 Qwen-ASR。Qwen-ASR 模式只接管最终音频段，滚动检查点仍由 Whisper 处理；Qwen 异常时自动回退 Whisper Medium。Qwen-ASR 与 Qwen3.5 翻译可以同时驻留，统一通过 MLX 互斥锁串行推理。Whisper 模式的选择性后台复核任务仍全局最多 1 个，并受队列和前台空闲窗口约束。
9. 复核结果通过质量门控后还要满足高一致度：普通候选 ≥0.86，数字候选 ≥0.80；只有最终短缩等有独立证据的情况允许专门阈值。证据不足时保留首版，不发布“更流畅但失真”的改写。
10. 修正携带 `utterance_id / batch_id / revision` 回到 semantic worker；缓冲内精确替换对应片段，已翻译批次则重新入队。同一批次的旧译文不能覆盖新 revision，翻译上下文也替换而非追加旧版本。
11. `voice_status` 暴露后台 active/queued/applied/discarded 以及 Qwen available/queued/success/fallback 计数；日志记录复核引擎、耗时、一致度、原因和决策。

### 6. Epoch 隔离（防设置切换串台）

- 全局 `SESSION_EPOCH` 原子计数，任何设置变更 +1
- 识别/翻译完成时校验起始 epoch，不匹配丢弃；停止语音也提升 epoch，快速重启不会收到旧会话尾包
- 参考 Hen 的 direction_epoch 设计

### 7. 翻译有序队列与上下文窗口

- 专用 translation worker 按说话顺序消费任务，`TRANSLATE_GATE` 继续与手动文本翻译互斥
- 停止或切换设置后，旧 epoch 队列任务会被丢弃，不向界面发布过期结果
- 三档语音模式均以 Hy-MT2 作为前台首译；翻译完成后立即发布，不等待 MLX 模型。Qwen3.5 常驻 JSONL/MLX worker 只承担选择性异步复核，空闲 600 秒退出。
- 每个翻译任务显式携带独立的 `source_language / target_language`；上下文窗口按 epoch、源语言、目标语言和模型共同隔离，固定多语言目标不再落入旧的中英方向分支。
- 首译与复核候选都必须通过文字系统检查和离线 Whatlang 语言识别。错误语言会无上下文严格重试一次；再次失败则拒绝发布。均衡档只复核数字、否定、遗漏、术语等客观风险，高质量档额外允许上下文风险，极速档完全关闭翻译复核。
- 复核候选还需通过上下文泄漏、长度、数字、人名、术语和语义一致性门控；证据不足时保留 Hy-MT2 首版，避免纯风格改写造成字幕跳动。
- 每次翻译最多带入最近 2 组、合计不超过 320 字符的同 epoch / 同源语言 / 同目标语言 / 同模型原文与译文；历史以已完成的 user/assistant 翻译对传入，当前原文始终是最后一条 user 消息，提示词明确只翻译当前句。
- 输出层会提取模型偶发返回的 `translation/current_translation/current_source/output` JSON 字段；检测到上下文复制、长度膨胀、新增人名/数字时自动去掉历史重试。术语未按指定写法输出时，改用 `ZXQTERM...QXZ` 保护标记重试并在 Rust 侧恢复目标词。
- 成功翻译后才写入窗口；epoch 变化立即清空，避免方向、模型或会话切换串台。

### 8. 实时指标与自动调参

- ASR、翻译执行和翻译排队延迟使用 α=0.2 的 EWMA；同时记录最近 24 个最终结果的质量异常、ASR/翻译队列峰值、RMS、噪声底和 Silero 概率。
- 至少积累 8 个最终样本后，异常率达到 20% / 40% 时把 fast 模式尾音补偿目标调整为 +80 / +160ms；每次最多上调 40ms、下调 20ms。候选断句已有 220ms 后滚时只追加目标的一半，稳定后逐步恢复为 0。
- steady 模式不应用动态补偿；切换麦克风/系统音频时清空质量窗口，避免不同声学环境相互污染。
- UI 标题栏显示 ASR/翻译 EWMA，完整指标由 `voice_status.quality_metrics` 暴露，可直接用于后续真实会话阈值回归。

### 9. 口译模式 + 防自激

- `say` 命令朗读（中文 Tingting / 英文 Samantha 自动选择）
- 朗读期间 `is_self_speaking()` 为真 → VAD 循环 `continue`（麦克风静音）
- 估算朗读时长（4字/秒+1s余量）作为静音窗口

## Tauri 2 无模板开发的四个坑（必读）

| 坑 | 现象 | 解法 |
|---|---|---|
| `withGlobalTauri: true` 缺失 | 前端 JS 第一行就死（`window.__TAURI__` undefined） | tauri.conf.json → app 节点添加 |
| UI 编译期嵌入 | 改了 index.html 不生效 | `rm -rf target/debug/build/my-translator-*` 后重编（**brotli 压缩存储，strings 搜不到明文**） |
| capabilities 权限 | 事件 listen 被静默拒绝 | `capabilities/default.json` 授权 `core:event:default` 等 |
| 事件负载结构 | 页面显示 `[object Object]` | Tauri 2 优先读 `e.payload`，再兼容 `e.data` / 直接负载 |

## 后端命令清单（invoke_handler）

| 命令 | 功能 |
|---|---|
| `translate(text, direction, model)` | 文本翻译 |
| `start_voice / stop_voice / voice_status` | 语音管线控制 |
| `set_asr_lang / get_asr_lang` | 识别语言（zh/en/auto） |
| `set_vad_mode` | 断句模式（fast/steady） |
| `set_voice_input` | 下次采集使用 microphone/system |
| `get_last_subtitle` | 最近字幕（轮询兜底） |
| `toggle_speak / is_speak_on` | 口译模式开关 |
| `get_glossary / save_glossary` | 读取/原子保存双向术语表 |
| `show_overlay / hide_overlay` | 悬浮字幕控制 |

## 前端事件流

| 事件 | 负载 | 消费方 |
|---|---|---|
| `voice-partial` | string（预览文本） | 主窗口左栏流式预览 / 悬浮窗灰字 |
| `voice-heard` | {id, source} | 主窗口立即新增识别片段，右栏先显示“翻译中…” |
| `voice-semantic-merged` | {source, fragment_ids} | 把多个短片段的待翻译行收拢为完整语义行 |
| `voice-translated` | {source, translation, fragment_ids} | 按片段 ID 精确更新右栏 / 悬浮窗白字 |
| `voice-semantic-cancelled` | {fragment_ids} | 清理停止或设置切换后的旧缓冲行 |
| `voice-error` | string | 主窗口左右栏错误行 |

## 构建与部署

```bash
# 模型必须齐全、哈希一致，且 models/ 内不允许外部软链接

# 开发（UI 变更后必须清缓存）
rm -rf target/debug/build/my-translator-*
cargo build

# 打包 .app
./make-app.sh
open MyTranslator.app

# 打包 DMG（拖拽安装）
./make-dmg.sh
```

## 性能基准（Apple Silicon 24GB）

### 10 条冒烟套件 × 3

- 最终 ASR：whisper medium 常驻服务，P50 0.654 秒，P95 0.843 秒
- 快速预览：whisper base 单飞识别，首次切片 550ms，推理约 0.2 秒
- 前台翻译：Hy-MT2 Q4_K_M，术语保护开启，P50 0.250 秒，P95 0.311 秒
- 后台翻译复核：Qwen3.5-2B MLX 4bit，仅风险门控命中且前台空闲时异步运行；数字、否定、术语、长度、上下文泄漏和 epoch 共同决定是否应用
- 快速模式停顿→译文：P50 1.331 秒，P95 1.539 秒
- 术语保持率：100%；中文 CER 7.62%，英文 WER 3.77%
- 双引擎完整冷启动预热：约 10 秒

### 200 条 FLEURS 真实人声 × 1

- 中文 CER 8.92%，英文 WER 5.67%，ASR 完全一致率 37.00%
- 翻译 chrF 46.40%（单参考译文，仅适合回归比较）
- ASR P50/P95 0.833/1.199 秒；翻译 P50/P95 0.375/0.703 秒
- 以 420ms 长句尾静音预算计，端到端 P50/P95 1.623/2.271 秒
- 中文/英文录音中位时长 11.79/9.96 秒，超过快速模式 8 秒最大单段，属于长句压力测试

运行 `python3 tools/prepare_fleurs200.py --download --remove-archives` 可复现数据集，再运行 `python3 tools/benchmark_realtime.py --suite benchmarks/suites/fleurs200.jsonl --tag fleurs200` 生成报告。

## 已知限制

1. 历史 UI 列表重启即失（transcript md 持久化兜底）
2. 麦克风模式没有真 AEC（朗读静音门控替代）；播放视频/会议建议直接使用系统音频模式
3. 流式 partial 为切片重识别（非原生流式解码）
4. Windows/Linux 未适配（whisper.cpp/llama.cpp 跨平台，理论可行）
5. FLEURS 已覆盖 200 条真实人声，但用户实际会议、远场、噪声和专用术语仍需单独采样
